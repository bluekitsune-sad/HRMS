PRD — Creative Studio HRMS
Product Name: ArtFlow HRMS Product Type: HRMS + Creative Workforce & Task Management Target Organization: Digital Art / Illustration / Animation / Comic Studio Frontend & Backend: Next.js Database: MongoDB Authentication: NextAuth/Auth.js or custom JWT/session authentication File Storage: S3-compatible object storage / Cloudinary Notifications: Email + in-app notifications + optional WhatsApp integration Deployment: Vercel + MongoDB Atlas

1. Product Vision
ArtFlow is an internal platform designed specifically for digital art studios.
Traditional HR systems answer:
"Who works here?"
ArtFlow should answer:
"Who works here, what are they good at, what are they currently working on, what can they pick up next, how are payments handled, and what is happening across the studio?"
The system combines:
HR management
Employee self-service
Attendance
Leave
Payroll/payment records
Payment-proof management
Recruitment
Artist profiles
Skills and portfolios
Creative task management
Artist workload
Equipment management
Project management
Performance
Studio analytics

17. Preventing Two Artists From Claiming the Same Task
This needs to be handled at the backend/database level.
Two artists could click:
CLAIM
at almost exactly the same time.
Your API should perform an atomic database update so only one succeeds.
Conceptually:
Task status = OPEN

        ↓

Artist A → CLAIM
Artist B → CLAIM

        ↓

Database atomic operation

        ↓

Artist A → SUCCESS
Artist B → TASK ALREADY CLAIMED

This is a great technical detail to mention in your presentation because it demonstrates that the application isn't just a frontend demo.

39. Security Requirements
Because this is an HR application, security needs to be taken seriously.
Implement:
Role-based access control.
Server-side authorization.
Password hashing if using password auth.
Secure sessions.
Input validation.
File type validation.
File size limits.
Audit logs.
Rate limiting.
Secure document access.
Encryption in transit.
No salary data exposed to unauthorized users.
Especially:
Never rely on hiding UI buttons as authorization.
If an employee shouldn't see payroll data, the API/server must reject the request too.

43. Final Product Positioning
I'd actually avoid calling it simply "HRMS" when presenting it.
Call it:
ArtFlow — Creative Studio Operating System
Tagline
People. Projects. Artists. Payments. One Studio.
The HRMS is the foundation, but the differentiator is the creative workforce layer.
Your three strongest selling points would be:
Creative Task Marketplace
Artists can discover and claim work while management sees ownership and progress in real time.
Artist Intelligence
Skills, portfolios, availability, workload and smart task matching help management put the right artist on the right project.
Studio Pulse
A management-level view of workforce health, project progress, capacity, bottlenecks and creative performance.
And the WhatsApp payment-proof system solves a very real operational problem: instead of payment screenshots disappearing inside chat conversations, they're attached to the employee/payment record and can be verified and audited.
If you build those pieces exceptionally well, you have something much more impressive than a generic employee CRUD application.
